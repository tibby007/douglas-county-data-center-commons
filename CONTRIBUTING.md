# Corrections and contributions

1. Record the case identifier, the field, the proposed correction, the official URL and its page or agenda item. The prototype offers no submission form.
2. Compare the proposed correction against the original source. Confirm the issuer, jurisdiction, dates, draft or final status, and what the record establishes. If records conflict, hold the change for review.
3. Use minimal factual fields. Document the source’s reuse limits in the [source register](docs/SOURCES.md). Keep third-party documents and personal contact details out of the project.
4. If the source is new, record its retrieval and review dates and the reviewer. Before any public release, have a human reviewer compare material claims with the original and record the result.
5. Update the claim version and add a history entry with the prior value, correction reason, source locator, and date. Keep prior versions recoverable through the repository and history.
6. Run the data validation and check the case page and both export formats. Update the coverage date only when the index review changes.

For maintenance, recheck the indexed source and source links before each release. Review any case-specific final decision separately from permit and operating status. The owner decides when to accept changes or release an updated index.
